# Sports Swipe

A web simulation of the Sports Swipe app: swipe Over or Under on real NFL and NBA
player lines with practice coins, build parlays, play free weekly contests, add
friends, create leagues and text invites from your own phone.

- `backend/`: Rust (Axum + SQLx) on Postgres. `api` serves `/v1/*`, invite
  landing pages (`/i/{token}`) and the web build; `worker` ingests ESPN data,
  creates lines, grades markets and runs contests.
- `app/`: Flutter app (web build runs inside a phone frame on desktop).
- `scripts/`: end-to-end checks over HTTP.

## Run locally

```sh
docker run -d --name ss-pg -p 5433:5432 -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=sportsswipe postgres:16
cp .env.example .env && set -a && source .env && set +a

# Load the NFL season and the last 21 NBA days, then create lines.
(cd backend && cargo run --release --bin worker -- backfill 21)

(cd app && flutter build web --release)
(cd backend && cargo run --release --bin api)      # http://localhost:8080
(cd backend && cargo run --release --bin worker)   # keep data, grading and contests current
```

Sign up with an email listed in `ADMIN_EMAILS` to get the admin screen
(Profile → Admin), where markets can be locked and settled with
`POST /v1/admin/settle-market`.

## Run in the iOS Simulator

Requires full Xcode (App Store) and CocoaPods (`brew install cocoapods`).

```sh
sudo xcode-select --switch /Applications/Xcode.app/Contents/Developer
sudo xcodebuild -runFirstLaunch
xcodebuild -downloadPlatform iOS          # simulator runtime, if Xcode didn't install one
open -a Simulator                         # boots an iPhone
(cd app && flutter run -d iPhone)         # the API must be running on localhost:8080
```

The simulator reaches the Mac's `localhost`. For a real iPhone on the same
Wi-Fi, run the API with `PUBLIC_BASE_URL=http://<mac-ip>:8080` and the app with
`flutter run --dart-define=API_BASE=http://<mac-ip>:8080`.

## Export collected data

```sh
API=https://sportsswipe.fly.dev ADMIN_EMAIL=you@example.com ADMIN_PASSWORD=... python3 scripts/export_data.py
```

Writes `exports/<timestamp>/` with `users.csv`, `picks.csv` (one row per
leg), `contest_entries.csv`, `contest_answers.csv` and `stats.json`, and
prints the headline numbers. Admin accounts are left out of the stats.

## Deploy (Fly.io + Tiger Cloud)

See the header of `infra/fly.toml`. One image runs two processes: `app`
(the API and web build) and `worker`. Set `DATABASE_URL` to the Tiger Cloud
connection string with `sslmode=require`.

Pack inventory checks use an isolated PostgreSQL database (the tests create and
remove their own databases; use a local test server with a database-creation role):

```sh
cd backend
DATABASE_URL=postgres://postgres:password@localhost:5432/postgres cargo test -p ss-db --test pack_inventory -- --ignored
```

Migration `0004_team_packs.sql` adds 50-coin packs for existing teams and keeps
new team imports synchronized. Packs contain five unique markets per purchase;
remaining counts share the user's unowned, unplayed market pool across offers.
The app persists the purchase command before sending it so recovery reuses the
server's idempotent purchase. Remaining open cards are also available in Leftovers.

Pack material audio is original synthesized Foley, generated by
`scripts/generate_pack_sounds.py`. Replace these four WAVs with recorded material
cues if a physical reference shoot is available. The wrapper uses Flutter canvas
geometry; no Blender renders or recorded pack footage are bundled. Test drag feel,
audio timing, haptics, and frame pacing on physical iPhone and Android hardware
before release.

Admin judging flow: **Collection → Diamond → Sell**.
The collection retains an explicitly marked fictional 400/400 admin Diamond grant.
There is no separate presentation pack. See [collectible setup](collectibles/README.md) for devnet
issuer and presentation-buyer configuration.

Card footer share arrows create ten-card head-to-heads. A friend receives the
invitation in Messages; an external invite opens `/duel/TOKEN` in a browser and
returns there after signup. Both players get the exact same frozen lines and
submit ten private picks plus a combined-total-points tiebreaker before the first
card locks. Scores use one point per correct call and then absolute tiebreaker
error; exact ties remain draws. These matches never award coins or mastery.
Head-to-heads appear in Social → Messages. Run
`scripts/test_presentation_head_to_head.py` against an isolated local API/DB for
admin permissions, frozen lines, invitation access, scoring, and zero coin effects.

### Analyst research

The analyst uses the server-only `GEMINI_API_KEY` (or `GOOGLE_API_KEY`) and
`GEMINI_ANALYST_MODEL` to interpret questions into validated research plans.
The currently verified model is `gemini-3-flash-preview`; configure another
supported model through that variable. No model key is sent to Flutter.

The model cannot issue SQL, execute code, choose network URLs, read account
records, or invent the statistics shown in a report. Rust reads final official
box-score revisions from the game database, supplements gaps with historical
ESPN player game logs or team schedules, and computes the answer and comparison.
Public source snapshots live in `analyst_source_cache`, separately from the
markets/settlement tables; on-demand research never grades picks or changes coins.

Supported research dimensions include NFL/NBA player statistics (including NFL
interceptions and NBA steals, blocks, and turnovers), opponent, home/away,
season range, regular season/playoffs, team wins/losses, score/margin, rest gaps,
and threshold frequency. Follow-up questions carry the last three research plans.
Unsupported conditions ask for clarification instead of being silently ignored.
Each plan is bounded to 15 seasons, 100 games when a last-N filter is requested,
and six model questions per user per minute. The last-N limit is applied AFTER
filters; unbounded cohort analyses use every verified game in the chosen years.

Rest means calendar days between **team** games in `America/New_York`; missed
player appearances do not become extra rest. The first game without a verified
prior game in that season is excluded from rest comparisons. Ties count in the
win/loss denominator. Postseason is excluded unless requested, and unknown/DNP
stat cells are excluded rather than counted as zero. The UI shows scope, sample
size, comparison cohort, a paged game log, source links, and caveats. Charts use
one scale for bars, grid, zero, and threshold; long histories scroll horizontally.

Run `cargo test --workspace` from `backend/`. The opt-in live integration check
is `python3 scripts/test_analyst_research.py`; it refuses non-local API hosts and
requires the dedicated test API/catalog (Josh Allen, BUF, BAL, DAL) and Gemini
key. It checks both example questions, a playoffs follow-up, deduplication,
source-cache reuse, and calculations. Targeted UI tests are
`flutter test test/research_chart_test.dart test/research_report_test.dart`.
